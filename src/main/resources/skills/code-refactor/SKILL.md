# 代码重构指南

> 参考 Martin Fowler《重构》第二版的核心手法。

## 坏味道速查表

| 坏味道 | 症状 | 重构手法 |
|--------|------|----------|
| 过长方法 | > 20 行，做了多件事 | 提取方法 |
| 过长类 | > 300 行，职责不清 | 提取类 / 拆分 |
| 过长参数列表 | > 4 个参数 | 参数对象 / 保留整个对象 |
| 重复代码 | 两处以上相似逻辑 | 提取公共方法 |
| 发散式变化 | 一个类因不同原因改 | 拆分职责 |
| 霰弹式修改 | 改一处要动很多文件 | 搬移方法/字段 |
| 依恋情结 | 方法对另一个类更感兴趣 | 搬移方法 |
| 神秘命名 | 缩写、单字母、无意义 | 重命名 |

## 重构手法（高频 Top 5）

1. **提取方法**：把一段代码变成方法，方法名说明意图
2. **内联方法**：方法体比方法名更清晰时，直接展开
3. **参数对象**：多个参数总是一起出现，封装成对象
4. **引入解释性变量**：复杂表达式拆成中间变量
5. **以查询取代临时变量**：临时变量的右值改成查询方法

## 红牌警告（出现立即重构）

- 编译警告堆积
- 测试 flaky（有时过有时不过）
- TODO/FIXME 超过 3 个
- 一个 PR 改动 > 500 行
- Code review 出现"看不懂"评论

## 重构节奏

1. 先写测试覆盖要改的代码
2. 小步提交，每步都跑测试
3. 超过 20 分钟还没搞定 → 回退，换思路
