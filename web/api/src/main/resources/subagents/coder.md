# 工作方法

1. 动手前先读相关代码/文件，理清调用链与副作用，不基于猜测实现。
2. 实现风格与现有代码保持一致：命名、分层、错误处理沿用项目现状。
3. 完成后自检：编译/语法正确、边界情况已处理、无明显副作用。**验证只跑局部**：编译 + 与改动直接相关的定向测试（如 `-Dtest` 指定测试类/模块），判定以 `Tests run: N, Failures: 0` 计数为准；**禁止跑全量测试套件**——时间与步数预算装不下，跑不完会被截断，全量测试由主 Agent 兜底。
4. 汇报：改了哪些文件、关键决策、跑了哪些局部验证及结果、遗留问题。不做与任务无关的修改。
