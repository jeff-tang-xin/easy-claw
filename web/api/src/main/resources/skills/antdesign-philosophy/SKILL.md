# Ant Design 设计理念

本 Skill 提供 Ant Design（v5 为主，标注 v4 差异）的设计语言，用于指导 UI 实现
与样式审查。目录下包含多个规则文件，按需查阅。

## 子规则索引

| 文件 | 覆盖范围 |
|------|----------|
| `tokens.md` | Design Token 完整速查：色彩/字体/间距/圆角/阴影/动效/层级/断点 |
| `components.md` | 组件规范：按钮/输入/表格/弹窗/消息反馈等 16 类组件的尺寸与状态 |
| `patterns.md` | 典型页面模式：应用骨架/查询列表/表单/详情/看板/结果/设置/登录 |
| `do-dont.md` | 正反例对照清单：八大维度的 ✅/❌，可直接当 UI 审查清单用 |

## 设计价值观（Why）

1. **自然（Natural）**——降低认知成本：符合直觉的交互、克制的动效、真实的数据呈现
2. **确定性（Certain）**——一致即可靠：同样的东西永远长一样、行为一样
3. **意义感（Meaningful）**——界面服务于任务，不为装饰而装饰
4. **生长性（Growing）**——设计系统可演进：Token 化，改一处全局生效

## 设计原则（How）

| 原则 | 含义 | 落地检查 |
|------|------|----------|
| 亲密性 | 相关内容靠近成组，无关内容拉开 | 同组元素间距 < 组间间距 |
| 对齐 | 一切对齐皆有理由 | 表单 label 对齐、卡片内容左对齐 |
| 对比 | 主次分明 | 主按钮每屏 ≤ 1 个；文字四级层次 |
| 重复 | 相同元素重复使用 | 同类操作用同款按钮/图标 |
| 直接 | 能直接操作不绕路 | 行内编辑优于弹窗编辑（低频复杂操作除外） |
| 高效 | 简化流程 | 默认值、快捷键、批量操作 |
| 即时反馈 | 操作必有响应 | hover/active/loading 状态齐全 |

## 快速参考（速查版，完整见 tokens.md）

### 色彩
- 主色 `#1677ff`（v4 为 `#1890ff`）；hover `#4096ff`、active `#0958d9`
- 文字四级：`rgba(0,0,0,0.88)` 主 / `0.65` 次级 / `0.45` 辅助 / `0.25` 禁用
- 功能色：成功 `#52c41a`、警告 `#faad14`、错误 `#ff4d4f`、信息 `#1677ff`
- 中性色：容器 `#ffffff`、填充 `#f5f5f5`、分割线 `#f0f0f0`、边框 `#d9d9d9`

### 字体与间距
- 基准 14px、行高 1.5714；标题 20/16/14
- 8px 栅格：间距取 8 的倍数（8/16/24/32）

### 形状与阴影
- 圆角：控件 6px、容器 8px
- 阴影极轻（三层复合）：`0 6px 16px rgba(0,0,0,0.08), 0 3px 6px -4px rgba(0,0,0,0.12), 0 9px 28px 8px rgba(0,0,0,0.05)`

### 动效与焦点
- 时长 0.3s、曲线 `cubic-bezier(0.645, 0.045, 0.355, 1)`；动效中庸不花哨
- focus 光环：`0 0 0 2px rgba(5,145,255,0.1)` + 边框变主色

## 在 Easy-Claw 项目中的应用

- 项目 `styles.css` 的变量映射：`--accent: #1677ff`、`--accent-dark: #0958d9`（已对齐 AntD）
- 主按钮 = 纯色主色 + hover 加深，**不用渐变**；每屏一个主按钮
- 分割线用比边框更淡的色阶（`#f0f0f0` 思路），边框与分割线分离
- 与 `frontend-quality` skill 配合使用：本 skill 定「长什么样」，frontend-quality 定「质量红线」（对比度/键盘可达/性能）

## 使用方式（按任务类型选入口）

| 任务 | 先读 |
|------|------|
| 新做页面/改布局 | `patterns.md` 对号入座选模式 |
| 写/改某个组件 | `components.md` 查该组件规范 |
| 定颜色/字号/间距 | `tokens.md` 查 Token |
| 评审/自查 UI | `do-dont.md` 逐条对照 |

### UI 审查清单（快速版，完整见 do-dont.md）

1. 主按钮是否唯一？危险操作是否有二次确认？
2. 文字是否分了层次（≥ 3 级灰）？正文对比度 ≥ 4.5:1？
3. 间距是否 8 的倍数？同组间距 < 组间间距？
4. 空态/加载态/错误态三态是否齐全？
5. 键盘是否可达？focus 是否可见？
6. 反馈是否分级（Message/Notification/Modal 用对场景）？
