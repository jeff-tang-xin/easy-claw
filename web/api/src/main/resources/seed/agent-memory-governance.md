# 持久化三层治理：MEMORY / knowledge / blackboard 分工与晋升规则

> 本条目为平台种子知识，是持久化分层的**元规则**：
> 规定其他知识该放哪、何时写、谁来修、何时销账、什么不配进。

## 一、三层各管什么

| 层 | 回答的问题 | 生命周期 | 写入时机 | 内容 |
|---|---|---|---|---|
| **MEMORY** | 我以后该怎么做？ | 跨会话，手动筛选 | 会话收尾时反思，少量 | 行为准则、偏好、工作方式（如「列目录用 list_files 不用 shell」） |
| **knowledge** | 世界是怎样的？ | 跨会话，工具化 | 事实出现时立即写 | 环境、路径、配置、约定、事实（如「18080 是后端端口」） |
| **blackboard** | 这次任务干得怎样了？ | 任务级，可被清理 | 发现即登记 | 结论 / finding / risk / note / 计划 |
| **最底层 prompt** | 我是谁、不能做什么？ | 模型级，极慎重 | 几乎不动 | 身份 + 安全红线 |

## 二、四条触发线（何时写哪层）

### 1️⃣ 漂移即修（knowledge，立即）
**发现 knowledge 与现状不符时，当场修正，不拖。**
- 主 Agent：可直接 `knowledge_write` 修正。
- 子 Agent：**绝不直接改 knowledge** —— 同名覆盖会丢失并发更新。
  子 Agent 只做一件事：blackboard 追加
  `note: 「knowledge <topic> 与现状不符：……（期望→实际）」`。
  主 Agent 在会话收尾或下次读到该条目时统一归口修正。
- 触发例子：条目写「列目录用 list_files」但实测 shell `ls` 也可用 → 漂移。

### 2️⃣ 收尾晋升（MEMORY，会话结束时）
**会话收尾时反思：「有什么下次还会再犯的错 / 下次还要再用的招？」**
- 有 → `memory_save` 写一行准则。
- 没有 → 不写。MEMORY 贵精不贵多。

### 3️⃣ 销账闭环（blackboard，立即）
**知识落库后，当场在黑板追加一条 note 销账：**
> `note: 「knowledge <topic> 已更新（vX → vY），要点：<一句话>」`

作用：
- 让其他 Agent 不用 diff 就知道某条知识变了。
- 让未来的自己能查到「这条知识是哪次任务修的」。

### 4️⃣ 二次踩坑（knowledge，立即）
**同一个坑第二次踩到，说明第一次没记或记错地方。**
立即把「坑的触发条件 + 正确做法」写进 knowledge，并注明「二次踩坑」。
这是 knowledge 最高优先级的补充信号。

## 三、blackboard 何时清理

黑板是任务级的，**不是越多越好**，但也不是「用完即焚」。

| 策略 | 说明 |
|---|---|
| **主 Agent 定期销账** | 一段工作收尾时，把「已完成、已落库」的条目标记为销账 note（见触发线 3️⃣）。 |
| **按主题清理** | 一个主题彻底完结（如「介入修复已上线」），该主题的条目可由主 Agent 视为已归档。 |
| **保留 finding / risk / conclusion** | 这些是「可复用结论」，只要还成立就不主动清。 |
| **黑板条数全局递增** | #157→#181 的跨会话递增说明：清理是「标记完成」，不是物理删除。 |

**核心原则**：blackboard 的「清理」= 销账归档（逻辑完成），不是删除。

## 四、谁负责修

- **知识库（knowledge）**：主 Agent 唯一归口。
  任何 Agent 都能写新条目；但**修正已有条目**只能由主 Agent 做，
  子 Agent 只能登记「漂移 note」（见触发线 1️⃣），否则并发覆盖丢更新。
- **记忆（MEMORY）**：主 Agent 自管，子 Agent 不碰。
- **黑板（blackboard）**：所有 Agent 都能写，只增不改。

## 五、什么配进知识库，什么不配

进 knowledge 的**三个判据**（同时满足）：
1. **跨会话有效**：明天、下周、换个 Agent 还用得上。
2. **客观事实**：路径、端口、配置、约定、命令、环境差异。
3. **漂移即修**：发现不对立刻改，不积压。

**不配进 knowledge 的**：
- ❌ 一次性任务的过程记录（那是 transcript）。
- ❌ 主观的「我觉得」「或许可以」（那是 MEMORY 的行为准则）。
- ❌ 安全红线（那是最底层 prompt）。
- ❌ 项目业务逻辑（那是代码注释和文档）。
- ❌ 临时中间态（如「我刚跑了测试，还没看结果」）。

## 六、口诀

- 事实 → knowledge，漂移即修。
- 准则 → MEMORY，收尾晋升。
- 进度 → blackboard，发现即登，落库即销。
- 红线 → prompt，慎之又慎。
- 同一个坑踩两次 → 立刻进 knowledge。
