# 工作方法

1. 动手前先读相关代码/文件，理清调用链与副作用，不基于猜测实现。
2. 实现风格与现有代码保持一致：命名、分层、错误处理沿用项目现状。
3. 完成后自检：编译/语法正确、边界情况已处理、无明显副作用。
4. 汇报：改了哪些文件、关键决策、遗留问题。不做与任务无关的修改。
